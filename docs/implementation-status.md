## 2. What is built

**Phase 0 — repository foundation.** Complete.

- `git init`; first commit preserved `AGENTS.md`, `INTEGRATIONS.md`,
  `opencode.jsonc` and `.env.example` byte-identical (exiting criteria of
  `planning/17` §Phase 0).
- Hygiene files: `.gitignore`, `.gitattributes`, `.editorconfig`, `.npmrc`,
  `README.md`, `SECURITY.md`, `.github/CODEOWNERS`, `.githooks/pre-commit`.
- ADR ratification: this document, §1.

**Phase 1 — toolchain, contracts, CI.** Complete, with the deviations in §4.

- pnpm 12 workspaces + Turborepo 2.11.8 task graph (`build`, `typecheck`, `test`,
  `test:integration`, `test:e2e`, `lint`, `clean`) with declared `dependsOn` and
  `outputs`, concurrency capped at 4 per `planning/05` §1.3.
- Directory skeleton from `planning/03` §5: 26 packages, 20 of them placeholders
  with a single `package.json` and no source.
- `backend/contracts` (`@ua/contracts`): Zod 4 schemas for task, risk, error and
  registry contracts, plus `generate-openapi.mjs` producing the committed
  `openapi.json` (12 schemas).
- `shared/logger` (structured JSON + redaction deny-list), `shared/error-handling`
  (error taxonomy → `ProblemDetails`), `shared/telemetry` (request id,
  traceparent, async correlation), `shared/test-utilities` (frozen clock,
  deterministic ids, two-org fixtures), `shared/typescript-config`.
- `.github/workflows/ci.yml`: `secret-scan`, `lint`, `verify` (ubuntu +
  windows matrix), `contract` (drift check on `openapi.json`).
- `infrastructure/docker/docker-compose.yml`: PostgreSQL 18 and Redis 8 with data
  on `./.data/` (gitignored, on `F:` with the repository).
- Startup/env config drift check (`scripts/check-env-example.mjs`) and secret
  scanning (`scripts/scan-secrets.mjs`) wired into both CI and the pre-commit
  hook.

**Phase 2 — identity, organizations, tenancy (in progress).**

- `backend/database` (`@ua/database`): Prisma 7.10 schema for `users`,
  `organizations`, `memberships`, `invitations`, `sessions`, `refresh_tokens`,
  `login_attempts`, `idempotency_keys` and `audit_events`; two migrations
  (`20251015_init_identity_tenancy` and `20261016_add_missing_tenancy_foreign_keys`)
  applied against PostgreSQL 18.
- The second migration closes a gap in the first: `idempotency_keys.organization_id`
  and `memberships.invited_by` were bare uuids, and `planning/06` §1 requires real
  FK constraints with `ON DELETE RESTRICT`. `test/schema.test.ts` now asserts that
  every `organization_id` is a real foreign key, so it cannot come back.
- The generated Prisma client is committed in full. `.gitignore`'s `models/` rule
  (for local model weights) also matched the client's own `models/` directory, so
  a fresh clone held an incomplete client; the rule now carves that path back in.
- Primary keys are `uuid` with a `uuidv7()` database default, generated by the
  database rather than the client. This closes the `[OPEN]` in `planning/06` §1:
  PostgreSQL 18 provides `uuidv7()` natively, so no ID library is added.
- `backend/database/test/schema.test.ts` holds the schema conventions from
  `planning/06` §1 as executable assertions: UUIDv7 keys, `timestamptz`
  timestamps, `organization_id` on every tenant table, credential columns
  confined to the four tables that need them, and `RESTRICT` (never `CASCADE`)
  on tenancy-root foreign keys.
- `backend/database/src/tenant.ts` is the tenant-scoped data-access layer
  (ADR-008). `forOrganization(prisma, organizationId)` returns a client whose
  every read and write against a tenant table has its `organization_id` filter
  injected, and whose creates are stamped with the scope's organization. It fails
  closed: a model that is not tenant-scoped, a relation-object write (which
  carries the organization as an object rather than the scalar the scope stamps),
  an unsupported operation, and any raw SQL all raise `TenantScopeError` instead
  of reaching the database unfiltered.
- `backend/database/test/integration/tenant-isolation.test.ts` is the Phase 2
  exit criterion: 15 cases proving a second organization's rows are invisible and
  unwritable through every path above, with a control case so isolation cannot
  pass against an empty database. It needs a live PostgreSQL, so it runs under
  `pnpm test:integration`, not `pnpm test` — the unit suite stays database-free
  for the CI matrix. `.github/workflows/ci.yml` gains an `integration` job with a
  PostgreSQL service that applies the migration and runs the suite.
- `test/schema.test.ts` also pins the layer to the schema: every model carrying
  `organization_id` must be in the scope, and the scope's relation-field map must
  match the schema, so drift is a test failure rather than a silent hole.

**Phase 2 — the API slice (`backend/apps/api`, `@ua/api`).** Built.

- NestJS 12 on the Fastify 5 adapter, assembled by `src/app.ts` (`createApp`), so
  the production entrypoint (`main.ts`) and the integration tests boot the same
  wiring. `reflect-metadata` is imported first in `app.ts`: without it Nest's
  dependency scan throws a `TypeError` that `logger: false` hides and
  `process.exit(1)` reports as a bare exit code.
- Routes: `POST /v1/auth/register` (201), `POST /v1/auth/login` (200),
  `POST /v1/auth/refresh` (200), `POST /v1/auth/logout` (204), `GET /v1/me` (200),
  `GET /v1/organizations`, `POST /v1/organizations` (201),
  `GET /v1/organizations/:orgId`, `GET /healthz`, `GET /readyz`.
- `AuthGuard` is registered as a global `APP_GUARD` and denies by default: a route
  is anonymous only where `@Public()` says so. Unsafe methods additionally require
  the CSRF double-submit — the `ua_csrf` cookie plus the matching `x-csrf-token`
  header, both checked against a value derived from the session, so a sibling
  subdomain that can set a cookie still cannot forge the request.
- Sessions are opaque tokens stored as hashes. Registration, login and refresh all
  rotate the session token; refresh tokens are one family per session and a reused
  token revokes the family (`reason: refresh_token_reused`). The unscoped Prisma
  client is confined to `src/identity`, `src/auth`, `src/organizations`,
  `src/audit` and the `src/health` readiness probe, and
  `test/unscoped-client.test.ts` fails if any other module reaches for it.
- Constructor dependencies are **value** imports. With `emitDecoratorMetadata`,
  an injected class imported via `import type` degrades to `Function` and Nest
  cannot resolve it; the module must import the class as a value (a DI failure is
  a boot failure, not a per-request one).
- Errors are answered as Problem Details by a global filter; validation is Zod
  through a pipe; the unique-violation check understands Prisma 7's driver-adapter
  error shape (`meta.driverAdapterError.cause.constraint.index`), not only the
  older `meta.target`, so a duplicate email is a 409 rather than a 500.

**Not built:** the desktop/agent runtime, RLS policies, Terraform, and everything
from Phase 3 onward. There is no agent loop, no tools, no approvals, and no
frontend code.

## 4. Deviations from the plan

**1. No GitHub remote — CI is written but unproven.**
`planning/17` §Phase 1 exit criteria say "CI green on both OSes". This repository
is local-only; creating a remote and enabling branch protection requires the
owner (`AGENTS.md` asks before anything irreversible). The workflow is therefore
`[UNVERIFIED]`. Action: create the remote, push, and check that `verify` and
`contract` pass on Windows as well as Linux.

**2. MinIO is not in the compose file.**
`planning/05` §5 step 5 says `docker compose up postgres redis minio`. As of
2026-10-15 `minio/minio` returns HTTP 401 for an anonymous pull, and
`bitnami/minio` and `scality/cloudserver:latest` are 404. Two S3-compatible
images were verified pullable: `chrislusf/seaweedfs` and `localstack/localstack`.
Object storage is not needed until Phase 2 (ADR-013), so the service is simply
absent rather than guessed at. **Open decision:** pick one before Phase 2, then
update `planning/05` §5 row 5.

**3. Q-T3 resolved as Biome.**
`planning/20` leaves the formatter/linter choice open: Biome vs ESLint + Prettier.
Chosen: **Biome 2.5.15** — one dependency, one binary, one config for lint and
format, and it holds up the exact-strictness TypeScript settings without plugin
version-skew risk (the failure mode `planning/05` Q-T1 warns about). Consequence:
the `shared/eslint-config` package named in `planning/03` §5 does not exist.

**4. `CONTRIBUTING.md` and `LICENSE` are not written.**
Both are listed as `[OPEN]` in `planning/17` §Phase 0 and `planning/15` §3
(licence choice unresolved — Q-DEV-6). `package.json` carries
`"license": "UNLICENSED"` as the honest interim value. README carries a short
contributing section in the meantime.

**5. `@types/node` is pinned to 24.19.2, not latest.**
Latest is 26.x, which describes Node 26's runtime. The runtime is Node 24 LTS
(ADR-014), so the matching type definitions are the correct pin.

**6. Build-script permission uses `allowBuilds`, not
`onlyBuiltDependencies`.** `pnpm-workspace.yaml` declares which dependencies may
run install scripts. The key originally used, `onlyBuiltDependencies`, is
**silently ignored** by pnpm 12 (this pnpm ships as a native binary and reads a
different schema than the pnpm 10 documentation describes). The correct key is
the `allowBuilds` map; `esbuild`, `prisma` and `@prisma/engines` are set to
`true`. Before the correction the declared policy was inert, so any dependency
could have run a postinstall script unnoticed.

**7. The development database is published on host port 55432, not 5432.**
`planning/05` §5 and the compose file originally used 5432. On this machine a
locally installed PostgreSQL service owns 5432, so Docker's port publish bound
nothing: host connections reached the native server and failed authentication
against a `universal_agent` role that does not exist there, while the same
password worked from inside the container network. The fix is a one-line default
change in `infrastructure/docker/docker-compose.yml` (`${POSTGRES_PORT:-55432}`),
and it is the better default anyway: 5433–5632 is reserved by Windows/Hyper-V
port exclusions, so a developer with a local PostgreSQL cannot use 5432 at all.
`backend/database/.env` points at 55432.

**8. Phase 2's cloud-foundation deliverables are deferred.**
`planning/17` §Phase 2 asks for a Terraform skeleton, a remote-state backend with
locking, and managed Postgres/Redis in dev/staging, with "Terraform plan is
reproducible" as an exit criterion. All of it is gated on the managed
Postgres/Redis provider choice (Q-T2), which is unresolved — Decision 6 in §5.
The same planning section says the choice is "needed before staging is real, but
not before local development", so Phase 2 is being built local-first and the
cloud foundation lands with the provider decision. Until then that one exit
criterion is unmet, and saying otherwise would be false.

**9. Row-level security is deferred to the gate the plan itself names.**
`planning/17` §Phase 2 lists "RLS as a backstop", but the same document puts
"RLS enabled and proven in production" at Phase 10, and `planning/06` §1 places
RLS at Phase 10 as well. Phase 2 builds the structural half — mandatory
`organization_id` on every tenant table plus a tenant-scoped data-access layer
whose queries cannot omit the filter — and the cross-tenant isolation suite
proves it. RLS is added at Phase 10, before paying customers and real data make
a mistake expensive. The isolation suite itself is **not** deferred:
`planning/17` §Phase 2 is explicit that deferring it is not acceptable.

**10. Biome needs two settings to lint the NestJS API.** Neither is a choice so
much as a requirement of the framework (`planning/20` Q-T3 chose Biome without
anticipating either, because Phase 1 had no decorators).

- `javascript.parser.unsafeParameterDecoratorsEnabled: true`. NestJS injects by
  parameter decorator (`@Body`, `@Param`, `@Req`, `@Inject`). Without this, Biome
  cannot parse a controller at all — every one is a parse error.
- `lint/style/useImportType` is turned **off** for `backend/apps/api/**`. Nest
  resolves a constructor dependency from the type in the decorator metadata that
  `emitDecoratorMetadata` writes, and a `import type` is erased before that
  metadata is emitted, so an injected class imported as a type degrades to
  `Function` and the app fails to boot. Biome's safe autofix rewrites exactly
  those imports to `import type`, so leaving the rule on means `pnpm format`
  silently breaks the server. Turning it off for the API package is the fix;
  every other package keeps the rule.
